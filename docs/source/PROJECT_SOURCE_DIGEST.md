**Report summary:** Streamlit web app that validates and preprocesses uploaded sales data (CSV/Excel), engineers lag, rolling, calendar, holiday and promotion features, trains ARIMA, Prophet, XGBoost and LSTM, compares them on hold-out data with MAE, RMSE, MAPE, selects the best, produces forecasts with confidence intervals, then an Inventory Recommendation module produces safety stock, reorder points, and stock-out/overstock alerts. Dashboard plus downloadable reports. The planner makes the final decision.

**Report objectives (9):** (1) build the system with ML and time-series analysis; (2) accept CSV/Excel and validate; (3) clean: missing values, duplicates, outliers; (4) engineer lag, rolling, seasonality, holiday, promotion features; (5) train ARIMA, Prophet, XGBoost, LSTM; (6) evaluate with MAE, RMSE, MAPE and auto-select best per product/category; (7) forecasts with confidence intervals for a daily/weekly/monthly horizon; (8) inventory recommendations (safety stock, reorder point, alerts); (9) Streamlit dashboard and downloadable reports.

**Report limitations:** depends on data quality and length; cold-start items cannot be forecast well; cannot predict unexpected external events; accuracy affected by missing promotion/price/weather info; LSTM needs more data and compute; needs periodic retraining; final decision stays with the human planner.

**Report modules (10):** Data Input, Data Preprocessing, Feature Engineering, Model Training, Model Evaluation, Forecast Engine, Inventory Recommendation, Dashboard, Report Generation, Planner Review.

**Report inputs:** sales (date, product ID, store/region, quantity); price and promotion; holiday/festival/calendar; stock levels and supplier lead time; user selections (product, horizon, model). **Outputs:** cleaned data, features, model comparison, forecast with confidence intervals, inventory recommendations, dashboard and reports.

**LSTM notes (the students' 12-step algorithm):** collect data (sales, market/external, inventory, orders, optional supplier) → check availability (if sources missing, continue with available ones and notify) → integrate and clean (merge, dedupe, handle missing, standardise date formats) → prepare sequences (e.g. 3 previous days predict next) → MinMax normalise → train LSTM → memory with forget, input, output gates and cell state → generate prediction → check accuracy (MAE, RMSE, MAPE; if poor, tune/retrain) → supply-chain decision (demand up: raise procurement, production, inventory; demand down: reduce) → continuously update with new actuals. Treat the typo "last short-time memory" as Long Short-Term Memory.
